# NT36532-driver

[English version](README.md)

[Как участвовать](CONTRIBUTING.ru.md) · [GPL-2.0-only](LICENSE)

Рабочее пространство Rust для драйвера Linux, который будет обслуживать дисплейную и сенсорную части контроллера Novatek NT36532.

| Крейт | Назначение |
| --- | --- |
| `panel-domain` | Жизненный цикл дисплея и порядок управления VDDIO, смещением матрицы, DSI и подсветкой |
| `panel-nt36532` | Последовательность сброса и DSI-команд NT36532 по переданному профилю панели |
| `panel-touch` | Разбор прошивки и декодирование касаний NT36532 |
| `panel-backlight` | Интерфейс управления яркостью |
| `panel-power` | Интерфейс управления питанием панели |
| `adapter-KTZ8866` | Адаптер подсветки и питания для пары KTZ8866. Шины и настройки задаёт плата. |

`kernel/Kbuild` собирает тач-модуль `nt36532`. С `KTZ8866_SRC` и профилем платы этот же модуль регистрирует двухканальную DSI-панель.

При сборке через Cargo передайте абсолютный путь к каталогу TOML-профилей
устройства в `TOUCH_PROFILES_DIR`. Для генерации профилей нужен Python 3.11
или новее. При загрузке `FirmwareImage::parse` ищет профиль по паре CRC
разделов ILM и DLM из заголовка образа. Неизвестные пары отклоняются.
Выбранный профиль доступен через `FirmwareImage::profile`.

Передавайте прошивку при запуске отдельным файлом. На Unix feature `std` даёт
доступ к `read_firmware_path` и `read_firmware_fd` для обычных файлов.
Чтение по fd начинается с нулевого смещения и сохраняет позицию дескриптора.
API без `std` принимает срез байтов через `FirmwareImage::parse`.

Для параметра запуска тач-модуля предусмотрен `FirmwareImage::parse_with_strategy`.
`TouchStrategy` принимает `auto`, `packed12-v1` и `big-endian16-v1`.
При явном выборе используется профиль с совпадающей парой CRC либо единственный
встроенный профиль указанного формата. Так можно задать стратегию и для образа
с неизвестной или другой парой CRC.

Linux-адаптер использует `request_firmware()` и требует
`CONFIG_FW_LOADER`. Имя прошивки задаётся относительно
каталогов поиска ядра. Буфер образа освобождается после запуска контроллера.
Чтение по файловому дескриптору доступно в userspace.

Из корня репозитория драйвера выполните сборку с подготовленным деревом ядра.
Используйте тот же Rust toolchain, которым собрано ядро. В
`TOUCH_PROFILES_DIR` передайте каталог профилей тачскрина платы.

```sh
make -C "$KERNEL_BUILD" M="$PWD/kernel" MO="$PWD/target/kernel" \
    PANEL_PROFILE="$PANEL_PROFILE" TOUCH_PROFILES_DIR="$TOUCH_PROFILES_DIR" modules
```

Перед переключением режима, при котором контроллер остаётся под питанием и
без аппаратного сброса, запишите `1` в `preserve_firmware_once` в каталоге
`/sys/module/nt36532/parameters/`. Этот одноразовый параметр позволяет
повторно использовать текущую прошивку при следующей подготовке панели.

Атрибут `touch_state` SPI-устройства в sysfs принимает `pause` и `resume`.
Пауза останавливает IRQ и отпускает активные касания и перо. Возобновление
ставит загрузку прошивки в очередь, если панель подготовлена.

Для сборки адаптера пары микросхем подсветки передайте в `KTZ8866_SRC` путь
к checkout KTZ8866-driver на ревизии из `crates/adapter-KTZ8866/Cargo.toml`.
Исходники драйвера остаются в отдельном репозитории.

Адаптер пары KTZ8866 регистрирует одно устройство Linux backlight
`ktz8866-backlight` для обеих половин панели. DRM включает подсветку после
подготовки панели и гасит перед отключением. Параметр запуска `boot_dark=1`
задаёт начальную яркость 0.

После применения патча DRM/MSM Kbuild подключает `set_live_refresh`.
Бесшовное переключение отправляет команды выбранного режима без сброса
панели и повторной отправки DSC PPS.
